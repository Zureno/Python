# UCAS — UDCRM Control Automation System

## Architecture & Microservices Overview

---

## 1. Executive Summary

**UCAS** (UDCRM Control Automation System) is a cloud-native platform that automates the validation of application security compliance across the enterprise. It replaces manual, error-prone compliance audits with a fully automated, nightly pipeline that:

- **Discovers** all in-scope applications from ServiceNow compliance indicators
- **Validates** each application against ASVS (Application Security Verification Standard) controls using data from multiple security tools — including Veracode, Invicti, GitHub CodeQL, Akamai, Harness, and others
- **Scores** compliance results and applies business-approved overrides
- **Reports** final compliance status back to ServiceNow automatically

### Key Outcomes

| Metric | Impact |
|--------|--------|
| **Automation** | Eliminates manual security compliance audits across all applications |
| **Coverage** | Validates against 10+ security tool integrations simultaneously |
| **Frequency** | Runs nightly — compliance status is never more than 24 hours stale |
| **Traceability** | Every pass/fail decision includes machine-generated evidence and finding URLs |
| **Scale** | Processes thousands of applications per cycle using parallel, event-driven architecture |

## 2. Architecture Overview

UCAS operates as a set of **17 serverless microservices** (AWS Lambda functions) orchestrated by **two AWS Step Functions state machines** that run on a nightly schedule.

### 2.1 Dispatch Orchestrator — Data Collection & Routing

> **Schedule:** Nightly at 10:00 PM CT (04:00 UTC)

Collects control definitions, discovers in-scope applications, builds validation queues, and dispatches work to validators.

## 7. Security & Compliance

| Aspect | Implementation |
|--------|---------------|
| **Authentication** | GitHub App authentication using JWT with short-lived installation tokens (55-minute expiry) |
| **Secrets Management** | All credentials (GitHub, ServiceNow, API keys) stored in AWS Secrets Manager — never hardcoded |
| **Encryption** | All DynamoDB tables encrypted with dedicated KMS keys with automatic key rotation enabled |
| **Container Security** | All Lambda Docker images run as `nonroot` user; security patches applied at build time |
| **Data Protection** | DynamoDB Point-in-Time Recovery enabled on all tables; deletion protection active |
| **Access Control** | IAM roles follow least-privilege; cross-account access via dedicated role stacks |
| **Change Streams** | All DynamoDB tables have change streams (`NEW_IMAGE`) enabled for audit trail |

## 8. Glossary

| Term | Definition |
|------|-----------|
| **AppCI** | Application Configuration Item — a unique identifier for an application in the CMDB |
| **ASVS** | Application Security Verification Standard — the set of security controls validated by UCAS |
| **UDCRM** | Unified Digital Compliance & Risk Management — the compliance framework in ServiceNow |
| **CWE** | Common Weakness Enumeration — a standardized list of software security weaknesses (maintained by MITRE) |
| **SAST** | Static Application Security Testing — analyzing source code for vulnerabilities (e.g., Veracode) |
| **DAST** | Dynamic Application Security Testing — testing running applications for vulnerabilities (e.g., Invicti) |
| **CodeQL** | GitHub's semantic code analysis engine for finding security vulnerabilities |
| **Control** | A specific security requirement that applications must comply with |
| **Validator** | A microservice that checks whether an application meets a specific control criteria |
| **Prescription** | The process of matching controls to applications based on entity attributes |
| **Override** | A manually approved exception that changes a validation result (e.g., accepted risk) |
| **Dispatch** | The process of routing validation work to type-specific queues for parallel processing |
| **Resolver** | The aggregation step that combines individual validator results into a single control-level result |
